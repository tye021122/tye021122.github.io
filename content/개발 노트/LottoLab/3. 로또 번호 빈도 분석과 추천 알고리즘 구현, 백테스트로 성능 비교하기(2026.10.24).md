# 1. 개요

이전 포스트에서는 로또 당첨 번호를 수집하고 SQLite 데이터베이스에 저장한 뒤, 중복과 누락을 확인하는 기능까지 구현했다

이번에는 저장한 데이터를 실제로 활용해 본다. 먼저 전체 기간과 최근 100회의 번호별 출현 빈도를 분석하고, 무작위 추천과 빈도 가중치 추천을 구현한다. 마지막으로 과거 시점으로 돌아가 번호를 추천하는 백테스트를 통해 두 접근의 결과를 비교한다

**이번 개발의 목표**
- 보너스 번호를 제외한 본 번호 6개의 출현 빈도 분석

데이터 수집 API는 다시 호출하지 않고 저장된 DB만 읽었다. 분석과 추천에는 Python 표준 라이브러리인 `sqlite3`, `collections.Counter`, `random`을 사용했다

# 2. 분석할 당첨 번호 불러오기
## 2.1 보너스 번호 제외

이번 분석은 대상은 본 번호 6개이다. 보너스 번호는 데이터베이스에 보관하지만, 빈도 집계와 추천 평가에는 포함하지 않는다

```Python
query = """
    SELECT round, num1, num2, num3, num4, num5, num6
    FROM lotto
    ORDER BY round DESC
"""
```

`get_draws()`는 위 쿼리로 회차와 본 번호 6개를 읽어 온다. 한 행의 첫 번째 값은 회차이고, `draw[1:]`은 본 번호 6개다

최신 회차부터 정렬하므로 `LIMIT 100`을 적용하면 최근 100회만 조회할 수 있다. 조회 개수는 `LIMIT ?`에 매개변수로 전달하고, 1 이상의 정수인지 검사한다

```python
show_frequency()           # 전체 기간
show_frequency(limit=100)  # 최근 100회
```

현재 DB에서 전체 분석 범위는 1~1246회, 최근 100회 범위는 1147~1246회다


## 2.2 번호별 출현 횟수 집계

```python
counts = Counter(
    number
    for draw in draws
    for number in draw[1:]
)
```

각 회차의 본 번호를 하나씩 꺼내 `Counter`로 집계한다. 결과를 출력할 때는 1~45번을 순회하므로 한 번도 등장하지 않은 번호도 0회로 표시할 수 있다

회차 대비 출현율은 다음과 같이 계산한다

```python
rate = counts[number] / len(draws) * 100
```

여기서 출현율은 **전체 회차 중 해당 번호가 본 번호에 포함된 회차의 비율**이다. 한 회차에 번호가 6개씩 포함되므로 45개 번호의 출현율을 모두 더하면 600%가 된다

공정한 추첨을 가정할 때 특정 번호가 한 회차의 본 번호에 포함될 확률은 6 / 45, 약 13.33%다. 따라서 N회에서 번호 하나의 기대 출현 횟수는 다음과 같다

```python
expected = N * 6 / 45
```

코드에서는 이를 ‘번호당 평균 출현 횟수’로 출력한다. 실제로도 전체 출현 횟수의 합이 항상 `N × 6`이므로 45개 번호의 평균과 일치한다. 다만 모든 번호가 정확히 이 횟수만큼 나와야 한다는 의미는 아니다

# 5. 빈도 가중치 번호 추천
## 5.1 과거 출현 횟수를 가중치로 사용

빈도 기반 추천은 자주 등장하는 번호에 더 큰 선택 가중치를 부여한다

```python
weights = [frequency[number] + 1 for number in candidates]
```

출현 횟수에 1을 더하는 이유는 한 번도 등장하지 않은 번호도 선택 가능하도록 하기 위해서다. 예를 들어 출현 횟수가 0회인 번호의 가중치는 1, 10회인 번호의 가중치는 11이 된다

이 값은 **추천 프로그램이 번호를 선택하는 가중치**이며, 실제 추첨에서 해당 번호가 당첨될 확률을 추정했다고는 볼 수 없다


## 5.2 중복 없이 6개 선택

`generate_numbers()`의 핵심 구조는 다음과 같다

```python
candidates = list(range(1, 46))
weights = [frequency[number] + 1 for number in candidates]
selected = []

for _ in range(6):
    index = rng.choices(
        range(len(candidates)),
        weights=weights,
        k=1
    )[0]

    selected.append(candidates.pop(index))
    weights.pop(index)

return sorted(selected)
```

`choices()`만 여러 번 호출하면 동일한 번호가 다시 선택될 수 있다. 따라서 번호를 하나 선택할 때마다 후보와 가중치를 함께 제거한다

첫 번째 선택에서는 각 번호의 가중치를 전체 가중치 합으로 나눈 비율에 따라 선택한다. 이후에는 남은 후보만으로 다시 선택한다. 따라서 처음 계산한 가중치 비율이 최종 6개 조합에 포함될 확률과 그대로 같지는 않다

# 6. 백테스트
## 6.1 평가 시점의 과거 데이터만 사용

이번 백테스트는 회차를 오름차순으로 정렬하고, 다음 순서를 반복한다
1. 평가할 회차 이전의 데이터로 빈도를 계산한다
2. 각 방식으로 5게임씩 추천한다
3. 해당 회차의 본 번호와 비교한다
4. 평가가 끝난 뒤 해당 회차 결과를 전체 빈도에 추가한다

|평가 대상|전체 빈도 학습 범위|최근 100회 학습 범위|
|---|---|---|
|101회|1~100회|1~100회|
|102회|1~101회|2~101회|
|1246회|1~1245회|1146~1245회|

앞에서 현재 DB의 최근 빈도를 분석할 때는 1147~1246회를 사용했다. 그러나 1246회를 평가할 때는 결과를 미리 볼 수 없으므로 1146~1245회를 사용한다

슬라이스의 끝인 `index`는 포함되지 않는다. 따라서 현재 평가 회차를 제외한 직전 최대 100개 회차만 사용한다

전체 빈도는 반복문을 돌면서 누적하지만, 현재 회차를 추가하는 코드는 반드시 평가가 끝난 뒤 실행한다

```python
# 현재 회차 추천 및 평가가 끝난 뒤 실행
full_frequency.update(draw[1:])
```

실행은 101회부터 평가하므로 최근 빈도도 항상 100회의 기록을 확보한다. 코드에서는 1회부터 마지막 회차까지 데이터가 연속되어 있는지도 확인하고, 누락된 회차가 있으면 백테스트를 중단한다


## 6.3 난수 시드와 비교 조건

```python
backtest(start_round=101, games=5, seed=42)
```

추천 방식마다 별도의 난수 생성기를 사용한다

```python
generators = {

입력한 기준 시드는 42지만, 실제로는 무작위가 42, 전체 빈도가 43, 최근 100회 빈도가 44를 사용한다. 각 방식이 다른 방식의 난수 소비에 영향을 받지 않도록 분리한 것이다

같은 데이터 코드 실행 환경에서는 결과를 재현할 수 있다. 다만 서로 다른 난수열로 한 번씩 비교한 결과이므로, 차이에는 추천 방식뿐 아니라 난수 선택의 우연도 반영된다

# 7. 백테스트 실행 결과
## 7.1 검증 조건

```

세 방식 모두 동일한 평가 회차에서 같은 수의 게임을 추천했다. 일치 개수는 다음과 같이 집합의 교집합 크기로 계산한다

```python
matched = len(set(numbers) & winning)
```


## 7.2 게임당 평균 일치 개수

|추천 방식|평균 일치 개수|무작위 대비 차이|
|---|---|---|
|무작위|0.7843|—|
|전체 빈도|0.7784|-0.0059|
|최근 100회 빈도|0.8045|+0.0202|

이번 실행에서는 최근 100회 빈도 방식이 가장 높은 값을 기록했다. 전체 빈도 방식은 무작위보다 조금 낮았다

공정하고 회차 간 독립적인 추첨을 가정하면, 과거 정보로 고른 서로 다른 번호 6개와 다음 당첨 번호의 기대 일치 개수는 다음과 같다

$$E[X] = 6 \times \frac{6}{45} = 0.8$$

이 기대값은 균등 무작위 추천뿐 아니라 과거 빈도로 선택한 조합에도 적용된다. 다음 추첨이 과거와 독립적이라면, 과거 정보를 이용해 어떤 6개 번호를 고르더라도 각 번호의 다음 회차 포함 확률은 같기 때문이다

세 결과 모두 0.8 근처에 있지만, 이것만으로 차이가 통계적으로 유의한지 판단할 수는 없다. 현재 결과는 **한 가지 시드 설정에서 관찰한 성능 차이**다

# 8. 추천 성능 비교와 추첨 편향 검증의 구분

이번 겨로가를 해석할 때는 두 질문을 구분해야 한다

| 구분        | 확인하려는 질문                                  | 이번에 수행한 내용               |
| --------- | ----------------------------------------- | ------------------------ |
| 추천 성능 비교  | 과거 빈도로 추천하면 무작위 추천보다 더 많이 맞히는가?           | 시간 순서 기반 단일 시드 백테스트      |
| 추첨의 편향 검증 | 관측된 추첨 결과가 공정, 독립 추첨 가정에서 기대되는 범위를 벗어나는가? | 빈도 요약만 수행, 별도 통계 검정은 미수행 |

최근 빈도 방식의 평균이 한 번 더 높았다고 추첨에 편향이 있다고 결론 내릴 수는 없다. 반대로 무작위와 비슷한 성능이 나왔다고 추첨의 공정성과 독립성이 증명되는 것도 아니다. 특정 추천 방식이 활용하지 못하는 편향이 있을 가능성도 있기 때문이다

현재까지 확인한 사실은 번호별 출현 횟수가 서로 다르고, 이번 백테스트에서는 최근 100회 빈도 방식의 평균 일치 개수가 가장 높았다는 것이다

추첨의 편향을 판단하려면 검정할 가설과 통계량을 정하고, 공정한 추첨에서도 어느 정도 차이가 발생하는지 별도로 비교해야 한다. 예를 들어 회차마다 45개 중 6개를 중복 없이 뽑는 모의 데이터를 생성해 실제 빈도의 불균형이 얼마나 이례적인지 확인할 수 있다

이때 한 회차의 번호 6개를 서로 독립인 6번의 복원 추출로 취급하면 안 된다. 실제와 같은 비복원 추출 구조를 반영해야 하며, 빈도의 균등성과 회차 간 독립성도 구분해서 살펴봐야 한다

따라서 이번 단계에서는 **추천 방식의 안정적인 우위를 확인하지 못했으며, 추첨의 편향 유무에 대한 통계적 결론도 내리지 않는다**

# 9. 다음 단계: 여러 시드로 반복 백테스트

다음에는 평가 회차와 회차당 추천 게임 수를 유지한 채, 기준 시드를 바꾸어 백테스트를 반복할 예정이다

확인할 내용은 다음과 같다
- 방식별 평균 일치 개수가 시드에 따라 얼마나 달라지는가
- 빈도 방식과 무작위 방식의 평균 차이가 반복해서 같은 방향으로 나타나는가
- 특정 방식의 우위가 일부 시드의 우연한 결과에 의존하는가
- 3개 이상 일치와 같은 적중 분포가 반복 실행에서 어떻게 달라지는가

반복 횟수와 사용할 시드 목록은 결과를 보기 전에 정한다. 잘 나온 시드만 골라 비교하지 않고, 모든 실행 결과를 함께 기록할 계획이다

여러 시드의 결과에서는 평균뿐 아니라 표준편차와 무작위 대비 차이도 정리한다. 같은 기준 시드 묶음에서 실행한 세 방식의 차이를 나란히 기록하면, 이번에 관찰한 최근 빈도 방식의 우위가 얼마나 안정적인지 확인할 수 있다

다만 시드를 바꿔도 평가에 사용한 과거 당첨 회차는 그대로다. 여러 시드 실험은 주로 **추천 과정의 난수에 따른 변동**을 살펴보는 것이며, 새로운 추첨 데이터를 확보하거나 추첨의 편향을 검정하는 실험과는 다르다

회차당 5게임은 같은 당첨 결과와 비교되므로, 추후 통계적 불확실성을 계산할 때도 모든 게임을 무조건 독립 표본으로 간주하지 않도록 주의할 예정이다
